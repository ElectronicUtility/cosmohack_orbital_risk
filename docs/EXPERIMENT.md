# Воспроизводимый эксперимент

Команда: `python scripts/research.py` из корня проекта; скрипт сам добавляет корень в import path. Он выполняет обычный расчет `run`, сохраняет полные JSON с provenance и только затем читает сохранённый каталог NOAA SEP для проверки. Исходные записи архивированы в `data/noaa/`, дата cutoff записана в каждом JSON. Baseline использует только последнюю суточную вероятность протонного события и переносит её на все окна одинаково, без траектории и временного пересечения.

* **Выраженное событие:** запрос 10.05.2024 06:00 UTC, cutoff 00:00. Доступный на cutoff выпуск RSGA 09.05 22:00 дал 50% вероятности. Проверочный каталог NOAA позднее зафиксировал начало 10.05 13:35 UTC, максимум 208 pfu в 17:45 UTC. Это проверка наличия события **в течение суток**, не доза на МКС и не факт воздействия в каждой из трех ВКД.
* **Контроль для этого механизма:** 02.05.2024 06:00 UTC, cutoff 00:00, вероятность 10%. В выбранном каталоге SEP нет записи о начале S1 в этот день. Это контроль отсутствия *записи о начале* в выбранном каталоге; он не доказывает отсутствие протонной обстановки в течение всех суток.
* **Проверка границы исторического вывода:** 05.05.2024 01:00 UTC, одночасовые окна, cutoff 04.05 23:00. Погодная линия даёт одинаковые 15% для всех окон. Реконструированная геометрия освещённости различается, но в strict replay она validation-only, как и historical conjunctions, поэтому решение остаётся `equivalent` по `space_weather`. Это намеренно показывает, что реконструкция не выдаётся за доступную на cutoff информацию.

Числовой Brier score для этих двух суток **не вычисляется**. Каталог начал SEP не предоставляет полную суточную бинарную разметку именно той величины, которую прогнозирует выбранный выпуск RSGA (`Proton`), а отсутствие начала 2 мая не равно отсутствию события на протяжении всего дня. Ранее полученное значение 0.13 было некорректной метрикой и из отчёта удалено. Baseline и погодная линия полной системы используют один внешний прогноз, поэтому на этих примерах преимущество в точности прогноза не установлено. Historical conjunction reconstruction также исключена из strict решения. Дополнительная информация полной системы — provenance, временная доступность, независимые current-факторы и явные ограничения. Для настоящей вероятностной валидации нужен полный независимый суточный ряд целевого события с совпадающей семантикой и больше двух наблюдений. Сохраненные файлы `research_results/{event,control,window_demo}.json`, соответствующие `.html` и `summary.json` содержат значения и исходные записи.
