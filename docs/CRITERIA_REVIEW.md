## Конкретные проблемы, воспроизведение и приоритет

1. **Автообновление текущего режима отсутствует.** `providers.fetch_current` обновляет данные лишь при обращении после TTL. В `app.js` расчёт вызывается формой/кнопкой; имеющийся интервал управляет анимацией. Нужен ограниченный частотой источников мониторинг активного current-режима и понятное время следующей проверки. Сохранённый анализ должен оставаться неизменяемым снимком. Затрагивает О5, Т1, Т6; прямое требование с. 3.

2. **Возраст источника заморожен на момент загрузки.** `current_conjunctions` и `current_provider_health` сравнивают `source_as_of` с `record.retrieved_at`. Если при загрузке выпуску было 11 ч 59 мин, через два часа кеш ещё допускается по TTL 6 часов и проверка возраста всё ещё видит 11 ч 59 мин вместо 13 ч 59 мин. Проверять надо возраст к моменту нового расчёта; время получения хранить отдельно. Обнаружено чтением веток кода; отдельного имитационного теста с часами в этой проверке не добавлялось.

3. **Флаг шестичасового горизонта неверно привязан к выпуску.** `analysis.conjunction_assessment` требует `coverage_start <= source_as_of`, затем проверяет шесть часов после source_as_of. В сохранённом реальном ответе source_as_of = 18.09.2026 22:16:38 UTC, начало покрытия = 23:00 UTC, конец = 25.09 23:00 UTC. Изолированная проверка с принудительно заданным статусом fresh дала `supports_next_6h_horizon=false`, хотя окно внутри покрытия. Это тест логики, **не утверждение свежести этого выпуска сейчас**. Нужна явная дата оценки и проверка её следующих шести часов; тест со стартом покрытия позже времени выпуска. Дефект метаданных не означает, что всё сравнение окон неверно: покрытие конкретного окна проверяется отдельно.

4. **Слабая экспериментальная проверка.** `EXPERIMENT.md` честно признаёт отсутствие доказанного превосходства над baseline. Нужна корректная разметка прогнозируемой величины, больше событий и контролей, сравнение на одинаковых cutoff/длительностях. Можно оценить устойчивость выбора окна и полезность предупреждений, не обязательно обучать ML или вычислять Brier без подходящей разметки. Отдельно проверить правило предпочтения большей дистанции при отсутствии ковариаций.

5. **Точность освещённости недостаточна для строгого ранжирования близких вариантов.** На 15.06.2024 для двухчасовых окон с 06:00 / 12:00 / 18:00 UTC шаг 5 мин даёт 55 / 65 / 50 мин тени; шаг 1 мин даёт 58 / 62 / 53; шаг 15 секунд даёт 56,75 / 62,25 / 52. Победитель в этом примере не меняется, но расхождение до 3 минут уже видно. Более мелкая сетка здесь не является внешней истиной. Нужны уточнение границ тени и проверка сходимости/независимым расчётом; сравнение с обоснованным допуском вместо нулевого.
