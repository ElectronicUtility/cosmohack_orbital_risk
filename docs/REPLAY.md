# Историческая реконструкция и strict replay

`reconstruction` принимает произвольное начало с 01.05 по 30.06.2024 и анализирует архивные данные без утверждения их point-in-time доступности. `replay` требует cutoff UTC не позже старта. Для погодной линии `archived_weather` отбрасывает выпуск, если позже cutoff находится либо его `:Issued:`, либо сохранённый ретроспективный HTTP `Last-Modified`, **до** передачи нормализованных событий анализатору. Локальные байты выпуска сверяются по SHA-256 с `data/noaa/availability_manifest.json`. `weather_assessment` повторно фильтрует нормализованные события по времени публикации. Если ни один допустимый выпуск не покрывает окно, состояние `insufficient`.

В текущем исследовательском наборе 57 выпусков 3-Day Forecast и 60 RSGA за май–июнь, плюс по одному граничному выпуску 30 апреля для 1 мая. При проверке одного двухчасового окна с началом в 06:00 UTC каждого из 61 дней и cutoff в 00:00 покрытие было найдено для всех дней; это не гарантирует покрытие любого cutoff или окна. Пропуски и различная семантика процентов не скрыты: источник и `quantity` входят в evidence. Окно за пределом горизонта остаётся без покрытия. `SEP page code.20241115.html` читается только `scripts/research.py` для проверки уже полученного результата; API расчёта его не импортирует.

Историческая орбита МКС берётся из 425 элементов соответствующего периода. Для реконструкции сближений используется отдельная зафиксированная выборка 532 989 TLE-строк / 4 580 объектов, покрывающая 29.04–02.07.2024. Источник содержит эпохи элементов, но не доказывает время публикации каждой строки и полноту каталога на исторический момент. Поэтому траектория, освещённость и сближения — **историческая reconstruction/validation** в обоих исторических режимах. Указание эпохи не подменяет publication time.

В strict replay `conjunctions` всегда имеет `decision_eligible=false`; отсутствие реконструированного прохода не считается благоприятным свидетельством. `lighting` также исключён из решения, если для исторической геометрии невозможно доказать availability к cutoff. Поэтому текущая строгая рекомендация в replay опирается только на подтверждённую погодную линию и может честно вернуть `equivalent` даже тогда, когда validation-геометрия различается между окнами.

Тесты `test_archived_release_respects_cutoff`, `test_archive_last_modified_after_cutoff_excludes_issue` и `test_future_event_and_revision_excluded_by_pipeline` подсовывают выпуск/редакцию после cutoff и проверяют отсечение до решения. `test_historical_orbit_never_uses_current_epoch` проверяет разделение орбит. Отдельные тесты проверяют, что исторические `conjunctions` и `lighting` не становятся decision-eligible в strict replay. В provenance-файлах сохранены ревизии, хеши, запросы извлечения и границы доказуемости источников.
