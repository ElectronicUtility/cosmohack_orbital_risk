# Историческая реконструкция и strict replay

`reconstruction` принимает произвольное начало с 01.05 по 30.06.2024 и анализирует выбранный архивный выпуск. `replay` требует cutoff UTC не позже старта. Слой `archived_weather` отбрасывает выпуск, если `:Issued:` позже cutoff, **до** передачи нормализованных событий анализатору. `weather_assessment` повторно фильтрует события по времени публикации. Выбор одного выпуска препятствует примешиванию поздней редакции. Если ни один выпуск не покрывает все сравниваемые окна, состояние `insufficient`.

В текущем исследовательском наборе 57 выпусков 3-Day Forecast и 60 RSGA за май–июнь, плюс по одному граничному выпуску 30 апреля для 1 мая. При проверке одного двухчасового окна с началом в 06:00 UTC каждого из 61 дней и cutoff в 00:00 покрытие было найдено для всех дней; это не гарантирует покрытие любого cutoff или окна. Пропуски и различная семантика процентов не скрыты: источник и `quantity` входят в evidence. Окно за пределом горизонта остаётся без покрытия. `SEP page code.20241115.html` читается только `scripts/research.py` для проверки уже полученного результата; API расчёта его не импортирует.

Историческая орбита берётся из 425 элементов соответствующего периода. Они извлечены из годового набора Space-Track, но их точное время публикации не подтверждено. Поэтому траектория и связанная с ней оценка освещённости — **историческая реконструкция** в обоих исторических режимах. Строгость утверждается только для погодной линии. Полная рекомендация при `replay` содержит явное ограничение об орбитальной реконструкции. Указание эпохи не подменяет публикационное время.

Тесты `test_archived_release_respects_cutoff` и `test_future_event_and_revision_excluded_by_pipeline` подсовывают выпуск/редакцию после cutoff. `test_historical_orbit_never_uses_current_epoch` проверяет разделение орбит. В файле `data/orbit_provenance.json` сохранены ревизия, запрос извлечения и граница доказуемости источника.
