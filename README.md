# Планирование ВКД на МКС — исследовательский прототип

Сервис для аналитика наземной группы: ввод начала, длительности (1–8 ч) и допустимого переноса старта (до 24 ч), расчёт трёх равных по длительности окон, траектории МКС, двух разных факторов и объяснимого сравнения. Он **не допускает** реальную ВКД и не вычисляет дозу космонавта или вероятность повреждения скафандра.

## Запуск из чистого окружения

Требуется Python 3.12 и доступ к интернету для текущего режима. Исторический архив NOAA и извлечённые элементы МКС включены в `data/`, поэтому исторический режим работает офлайн.

```powershell
cd <папка проекта>
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Текущий режим загружает [NOAA 3-Day Forecast](https://services.swpc.noaa.gov/text/3-day-forecast.txt) и [TLE МКС](https://celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=TLE). Произвольное начало с 1 мая по 30 июня 2024 года принимает историческая реконструкция; strict replay дополнительно требует cutoff не позже старта. В датах API нужен UTC offset (`Z` или `+00:00`).

```powershell
.venv\Scripts\python.exe -m pytest -q
$env:PYTHONPATH=(Get-Location).Path
.venv\Scripts\python.exe scripts/research.py
```

Исследовательские результаты создаются в `research_results/`; в поставке уже есть воспроизводимые примеры. Проверка API: `GET /api/health`; расчёт `POST /api/analyze`; сохранённый результат `GET /api/analyses/{id}`; экспорт `export.json` и `export.html`. JSON содержит запрос, окна, факторы, ссылки/хеши исходных записей и версии алгоритма. Исходные байты текущих запросов и использованных архивных выпусков пишутся в SQLite `data/analyses.db`.

## Семантика результата

Космическая погода: датированная **вероятность** солнечного протонного события или S1+ по NOAA/USAF, привязанная к суткам. Состояние `attention` означает превышение **экспериментального** порога 30%, задаваемого `EXPERIMENTAL_S1_ATTENTION_PERCENT`. Это не порог допуска ВКД. `forecast_below_experimental_threshold` означает только, что выбранный показатель ниже этого порога, а не безопасность. При отсутствии или устаревании данных вывод `insufficient`.

Второй механизм: попадание МКС в земную тень по орбите и приближённому направлению на Солнце. Влияние на выбор окна есть **только если пользователь отметил необходимость прямого солнечного света**. Это условие видимости/освещения работ, а не самостоятельное доказательство опасности. Расчёт сделан с шагом 5 мин; сравнение пересечений использует экспериментальный допуск 10 мин (`EXPERIMENTAL_COMPARISON_EPSILON_MINUTES`). При неизвестной орбите результат `insufficient`.

Сравнение не складывает факторы в общий балл: окно предпочтительно только при отсутствии ухудшения по обоим факторам и улучшении хотя бы по одному вне допуска. Также возможны `equivalent`, `tradeoff`, `insufficient`.

## Историческая честность

Архивные прогнозы выбираются только из выпусков с `:Issued:` не позднее cutoff. Поздние исправления не попадают в вычисление. Проверочный каталог протонных событий NOAA читается **только отдельным исследовательским скриптом** после расчёта. Исторические орбитальные элементы имеют эпоху, но в источнике нет доказанного времени публикации. Поэтому геометрия обозначена `historical_reconstruction_publication_unknown`; итоговый исторический расчёт сочетает строгий replay космической погоды с реконструированной геометрией. Нельзя считать весь вывод полноценным point-in-time прогнозом. Подробности в [docs/REPLAY.md](docs/REPLAY.md).

## Данные, сбои, конфигурация

Для имитации отключения установите `DISABLE_PROVIDERS=noaa_current` или `DISABLE_PROVIDERS=iss_current` (имена через запятую). При сбое используется помеченный старый кеш, если он есть; устаревший прогноз не приводит к благоприятной оценке. `COSMO_DB` меняет путь SQLite. Значения порогов выше экспериментальные. API-ключи не нужны. Лимиты NOAA/CelesTrak публичного доступа не подтверждены; сервис кеширует ответы на 60 и 120 минут соответственно. Смотрите [docs/SOURCES.md](docs/SOURCES.md), [docs/METHODOLOGY.md](docs/METHODOLOGY.md), [docs/EXPERIMENT.md](docs/EXPERIMENT.md) и [docs/TRACEABILITY.md](docs/TRACEABILITY.md).

## Границы готовности

Прототип проходит сквозные Current/Historical запросы и тесты, но не развёрнут по публичной ссылке и не содержит проверенной эксплуатационной модели условий ВКД. Исторический архив 3-Day Forecast имеет пропуски; ежедневный RSGA используется как продукт с иной семантикой вероятности. На неподходящем cutoff или вне горизонта честный результат — `insufficient`. Историческая орбита — реконструкция. В исследовании только два дня для проверки протонного прогноза, поэтому оно не доказывает калибровку вероятностей или превосходство над baseline.
