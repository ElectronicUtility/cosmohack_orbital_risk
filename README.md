# Планирование ВКД на МКС — исследовательский прототип

Сервис для аналитика наземной группы: ввод начала, длительности (1–8 ч) и допустимого переноса старта (до 24 ч), расчёт трёх равных по длительности окон, траектории МКС, двух разных факторов и объяснимого сравнения. Он **не допускает** реальную ВКД и не вычисляет дозу космонавта или вероятность повреждения скафандра.

## Запуск из чистого окружения

### Рабочее пространство

Интерактивная орбитальная схема, сравнение трёх вариантов начала и временная картина факторов, раскрываемые доказательства и режим показа для защиты. Первый экран открывает явно подписанный **сохранённый пример «Работа на свету» с конкретным предпочтительным временем**. Изменение формы требует настоящего пересчёта; прогноз и реконструкция остаются разными режимами.

Четыре раздела: `/planner` — планирование, `/archive` — поиск и повторное открытие расчётов, `/sources` — исходные записи, `/method` — правила сравнения. История новых расчётов хранит ссылки в браузере, сами результаты — на сервере. Обоснование переделки: [docs/UI_RESEARCH.md](docs/UI_RESEARCH.md).

Интерфейс работает из того же FastAPI, без сборки frontend и внешних CDN. Ссылки восстанавливают выбранный пример/сохранённый анализ и окно. Отчёты HTML и JSON содержат показанный результат. Подробности дизайна, ограничений и проверок: [docs/UI_DESIGN.md](docs/UI_DESIGN.md). Необязательные тесты слоя отображения: `npm test` (Node 20+, без установки npm-пакетов).

Требуется Python 3.12 и доступ к интернету для текущего режима. Перед запуском проверьте, что `python --version` показывает 3.12; если Python не добавлен в `PATH`, используйте полный путь к его `python.exe` в первой команде. Исторический архив NOAA и извлечённые элементы МКС включены в `data/`, поэтому исторический режим работает офлайн.

```powershell
cd <папка проекта>
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Для macOS/Linux:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Docker: `docker compose up --build -d`, адрес `http://127.0.0.1:8001`. База сохраняется в именованном томе `analyses`. Контейнер работает без root; проверка состояния: `/api/health`. Для публичного сервера нужен HTTPS reverse proxy к порту 8001 и постоянный том. Сам запуск Docker не создаёт публичную ссылку.

Откройте `http://127.0.0.1:8000`. Текущий режим загружает [NOAA 3-Day Forecast](https://services.swpc.noaa.gov/text/3-day-forecast.txt), [TLE МКС](https://celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=TLE) и [CelesTrak SOCRATES](https://celestrak.org/SOCRATES/) для текущего прогноза сближений. Произвольное начало с 1 мая по 30 июня 2024 года принимает историческая реконструкция; strict replay дополнительно требует cutoff не позже старта. В датах API нужен UTC offset (`Z` или `+00:00`).

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts/research.py
.venv\Scripts\python.exe scripts/validate_conjunction_reconstruction.py --start 2024-05-28T12:00:00Z --end 2024-05-28T16:00:00Z
```

Исследовательские результаты создаются в `research_results/`; в поставке уже есть воспроизводимые примеры. Проверка API: `GET /api/health`; расчёт `POST /api/analyze`; сохранённый результат `GET /api/analyses/{id}`; экспорт `export.json`, `export.html` и `bundle.zip`. JSON содержит запрос, окна, факторы, ссылки/хеши исходных записей и версии алгоритма. Исходные байты текущих запросов и использованных архивных выпусков пишутся в SQLite `data/analyses.db`.

## Семантика результата

Космическая погода: датированная **вероятность** солнечного протонного события или S1+ по NOAA/USAF, привязанная к суткам. Состояние `attention` означает превышение **экспериментального** порога 30%, задаваемого `EXPERIMENTAL_S1_ATTENTION_PERCENT`. Это не порог допуска ВКД. `forecast_below_experimental_threshold` означает только, что выбранный показатель ниже этого порога, а не безопасность. Трёхчасовой прогноз Kp из того же NOAA-продукта сохраняется только как контекст ожидаемой геомагнитной динамики и не преобразуется в дозу или второй риск-фактор. При отсутствии или устаревании данных вывод `insufficient`.

Второй механизм: потенциальные сближения МКС с каталогизированными объектами. В текущем режиме используется CelesTrak SOCRATES, который публикует рассчитанные TCA, минимальную дистанцию и относительную скорость для горизонта порядка семи суток; свежий полный выпуск поэтому явно проверяется на наличие не менее шести часов будущего покрытия. Порог 5 км — порог скрининга источника/реконструкции, **не** норматив ВКД. `Max Probability` SOCRATES не интерпретируется как вероятность попадания фрагмента в космонавта. В исторических режимах сближения восстанавливаются по TLE только как геометрическая reconstruction/validation: точные времена публикации элементов и полнота каталога на исторический момент не доказаны, поэтому этот фактор исключается из strict-replay решения.

Освещённость МКС остаётся дополнительным `plan_constraint`: она влияет на сравнение только если аналитик явно потребовал прямой солнечный свет. В strict replay историческая освещённость показывается как validation/reconstruction и не участвует в решении, потому что публикационное время исторических элементов неизвестно.

Сравнение не складывает факторы в общий балл. Используется Парето-сравнение только механизмов, допустимых для решения в выбранном режиме; возможны `preferred`, `equivalent`, `tradeoff`, `insufficient`, а также явный список исключённых механизмов и причин исключения.

## Историческая честность

Архивные погодные прогнозы выбираются только из выпусков, у которых и `:Issued:`, и сохранённый ретроспективный HTTP `Last-Modified` не позже cutoff; локальные байты дополнительно сверяются по SHA-256 с manifest. Поздние исправления не попадают в вычисление. Проверочный каталог протонных событий NOAA читается **только отдельным исследовательским скриптом** после расчёта. Исторические орбитальные элементы имеют эпоху, но в источнике нет доказанного времени публикации. Поэтому траектория, освещённость и исторические сближения обозначаются reconstruction/validation. Строгий point-in-time replay утверждается только для подтверждённой линии космической погоды. Подробности в [docs/REPLAY.md](docs/REPLAY.md).

## Данные, сбои, конфигурация

Для имитации отключения используйте `DISABLE_PROVIDERS=noaa_current`, `iss_current` или `socrates_current` (имена через запятую). При сбое используется помеченный старый кеш, если он есть; устаревший прогноз не приводит к благоприятной оценке. `COSMO_DB` меняет путь SQLite. `SOCRATES_SOURCE_MAX_AGE_MINUTES` задаёт инженерный предел свежести источника (по умолчанию 720 минут), а не эксплуатационный порог ВКД. API-ключи для используемых публичных endpoint не нужны. Лимиты NOAA/CelesTrak публичного доступа не подтверждены; TTL кеша: NOAA 60 мин, ISS TLE 120 мин, SOCRATES 360 мин. Смотрите [docs/SOURCES.md](docs/SOURCES.md), [docs/METHODOLOGY.md](docs/METHODOLOGY.md), [docs/EXPERIMENT.md](docs/EXPERIMENT.md) и [docs/TRACEABILITY.md](docs/TRACEABILITY.md).

## Границы готовности

Прототип проходит сквозные Current/Historical запросы и тесты. [Публичное демо](https://krotkoves.github.io/cosmohack_orbital_risk/) показывает сохранённые сценарии; новые расчёты требуют локального или отдельно размещённого FastAPI-сервера. [Сборка Pages](docs/PAGES.md). Проверенной эксплуатационной модели условий ВКД нет. Исторический архив 3-Day Forecast имеет пропуски; ежедневный RSGA используется как продукт с иной семантикой вероятности. На неподходящем cutoff или вне горизонта честный результат — `insufficient`. Историческая орбита и сближения — реконструкция; отсутствие реконструированного сближения не считается благоприятным доказательством. Погодная проверка охватывает 61 день: 60 размечены по сводкам NOAA SGAS, один исключён как неоднозначный. Из четырёх дней с событием предупреждение при пороге 30% обнаружило три; ложных тревог семь. Это проверка предупреждений по сводкам, не калибровка вероятностей. Отдельно проверены 108 окон освещённости и независимый солнечный расчёт ERFA. Текущее состояние и остающиеся внешние ограничения перечислены в [docs/STATUS.md](docs/STATUS.md).


## Версия для защиты 0.5.0

Вход для жюри: `/planner?example=sunlight&window=0`. Кнопка «Для защиты» укрупняет рабочий экран. Второй пример, «Свет или погодный прогноз», показывает конфликт условий. [Маршрут выступления](docs/DEMO.md), [карта исправлений](docs/JURY_FIXES.md).

На странице «Источники» кнопка «Исходные данные ZIP» выгружает `analysis.json`, автономный `report.html`, исходные байты, зависимости и `manifest.json` с контрольными суммами. Проверка без распаковки: `python scripts/verify_bundle.py orbital-risk-evidence.zip`. Это переносимый пакет доказательств; автоматического импорта чужой базы он не выполняет. Для воспроизведения расчёта используйте сохранённый запрос, ту же версию алгоритма и архив из репозитория. Текущие источники при повторной загрузке могут измениться.

`python scripts/build_demo_cases.py` пересчитывает два сценических примера; `python scripts/research.py` — три проверки прошлого решения; `python scripts/validate_planning.py` — серию по освещению. Полный запуск проверок: `python -m pytest -q` и `npm test`. Python 3.12 проверен в новом виртуальном окружении, фронтенд собира́ть не требуется.


## Проверки версии 0.6.0

Текущий план автоматически пересчитывается раз в пять минут на открытой странице. Запросы к источникам ограничиваются их TTL. Флажок позволяет остановить обновление; переход в архив/другой раздел или открытие сохранённого расчёта останавливает его. Редактирование плана и скрытая вкладка приостанавливают пересчёт. Каждый результат сохраняется отдельно. Возраст выпуска отсчитывается до текущего момента, а не до последней загрузки. NOAA старше 24 часов считается устаревшим.

`python scripts/validate_weather.py` воспроизводит погодную проверку офлайн по зафиксированным исходникам. `python scripts/fetch_validation_weather.py` повторно загружает проверочные SGAS; эти данные не используются в прогнозе. Детали и ошибки: [EXPERIMENT.md](docs/EXPERIMENT.md).

Независимая проверка геометрии: `pip install -r requirements-research.txt`, затем `python scripts/validate_solar_geometry.py`. Дополнительные библиотеки нужны только исследовательскому скрипту, а не сервису. Результаты сохраняются в `research_results/solar_validation.json`.
