# Планирование ВКД на МКС — исследовательский прототип

Сервис для аналитика наземной группы: ввод начала, длительности (1–8 ч) и допустимого переноса старта (до 24 ч), расчёт трёх равных по длительности окон, траектории МКС, двух разных факторов и объяснимого сравнения. Он **не допускает** реальную ВКД и не вычисляет дозу космонавта или вероятность повреждения скафандра.

## Запуск из чистого окружения

Требуется Python 3.12 и доступ к интернету для текущего режима. Исторический архив NOAA и извлечённые элементы МКС включены в `data/`, поэтому исторический режим работает офлайн.

```powershell
cd <папка проекта>
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Текущий режим загружает [NOAA 3-Day Forecast](https://services.swpc.noaa.gov/text/3-day-forecast.txt), [TLE МКС](https://celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=TLE) и [CelesTrak SOCRATES](https://celestrak.org/SOCRATES/) для текущего прогноза сближений. Произвольное начало с 1 мая по 30 июня 2024 года принимает историческая реконструкция; strict replay дополнительно требует cutoff не позже старта. В датах API нужен UTC offset (`Z` или `+00:00`).

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts/research.py
.venv\Scripts\python.exe scripts/validate_conjunction_reconstruction.py --start 2024-05-28T12:00:00Z --end 2024-05-28T16:00:00Z
```

Исследовательские результаты создаются в `research_results/`; в поставке уже есть воспроизводимые примеры. Проверка API: `GET /api/health`; расчёт `POST /api/analyze`; сохранённый результат `GET /api/analyses/{id}`; экспорт `export.json` и `export.html`. JSON содержит запрос, окна, факторы, ссылки/хеши исходных записей и версии алгоритма. Исходные байты текущих запросов и использованных архивных выпусков пишутся в SQLite `data/analyses.db`.

## Семантика результата

Космическая погода: датированная **вероятность** солнечного протонного события или S1+ по NOAA/USAF, привязанная к суткам. Состояние `attention` означает превышение **экспериментального** порога 30%, задаваемого `EXPERIMENTAL_S1_ATTENTION_PERCENT`. Это не порог допуска ВКД. `forecast_below_experimental_threshold` означает только, что выбранный показатель ниже этого порога, а не безопасность. Трёхчасовой прогноз Kp из того же NOAA-продукта сохраняется только как контекст ожидаемой геомагнитной динамики и не преобразуется в дозу или второй риск-фактор. При отсутствии или устаревании данных вывод `insufficient`.

Второй механизм: потенциальные сближения МКС с каталогизированными объектами. В текущем режиме используется CelesTrak SOCRATES, который публикует рассчитанные TCA, минимальную дистанцию и относительную скорость для горизонта порядка семи суток; свежий полный выпуск поэтому явно проверяется на наличие не менее шести часов будущего покрытия. Порог 5 км — порог скрининга источника/реконструкции, **не** норматив ВКД. `Max Probability` SOCRATES не интерпретируется как вероятность попадания фрагмента в космонавта. В исторических режимах сближения восстанавливаются по TLE только как геометрическая reconstruction/validation: точные времена публикации элементов и полнота каталога на исторический момент не доказаны, поэтому этот фактор исключается из strict-replay решения.

Освещённость МКС остаётся дополнительным `plan_constraint`: она влияет на сравнение только если аналитик явно потребовал прямой солнечный свет. В strict replay историческая освещённость показывается как validation/reconstruction и не участвует в решении, потому что публикационное время исторических элементов неизвестно.

Сравнение не складывает факторы в общий балл. Используется Парето-сравнение только механизмов, допустимых для решения в выбранном режиме; возможны `preferred`, `equivalent`, `tradeoff`, `insufficient`, а также явный список исключённых механизмов и причин исключения.

## Историческая честность

Архивные погодные прогнозы выбираются только из выпусков, у которых и `:Issued:`, и сохранённый ретроспективный HTTP `Last-Modified` не позже cutoff; локальные байты дополнительно сверяются по SHA-256 с manifest. Поздние исправления не попадают в вычисление. Проверочный каталог протонных событий NOAA читается **только отдельным исследовательским скриптом** после расчёта. Исторические орбитальные элементы имеют эпоху, но в источнике нет доказанного времени публикации. Поэтому траектория, освещённость и исторические сближения обозначаются reconstruction/validation. Строгий point-in-time replay утверждается только для подтверждённой линии космической погоды. Подробности в [docs/REPLAY.md](docs/REPLAY.md).

## Данные, сбои, конфигурация

Для имитации отключения используйте `DISABLE_PROVIDERS=noaa_current`, `iss_current` или `socrates_current` (имена через запятую). При сбое используется помеченный старый кеш, если он есть; устаревший прогноз не приводит к благоприятной оценке. `COSMO_DB` меняет путь SQLite. `SOCRATES_SOURCE_MAX_AGE_MINUTES` задаёт инженерный предел свежести источника (по умолчанию 720 минут), а не эксплуатационный порог ВКД. API-ключи для используемых публичных endpoint не нужны. Лимиты NOAA/CelesTrak публичного доступа не подтверждены; TTL кеша: NOAA 60 мин, ISS TLE 120 мин, SOCRATES 360 мин. Смотрите [docs/SOURCES.md](docs/SOURCES.md), [docs/METHODOLOGY.md](docs/METHODOLOGY.md), [docs/EXPERIMENT.md](docs/EXPERIMENT.md) и [docs/TRACEABILITY.md](docs/TRACEABILITY.md).

## Границы готовности

Прототип проходит сквозные Current/Historical запросы и тесты, но не развёрнут по публичной ссылке и не содержит проверенной эксплуатационной модели условий ВКД. Исторический архив 3-Day Forecast имеет пропуски; ежедневный RSGA используется как продукт с иной семантикой вероятности. На неподходящем cutoff или вне горизонта честный результат — `insufficient`. Историческая орбита и сближения — реконструкция; отсутствие реконструированного сближения не считается благоприятным доказательством. В исследовании только два показательных дня, и каталог начал SEP не даёт полной суточной разметки для расчёта качества вероятностного прогноза. Текущее состояние и остающиеся внешние ограничения перечислены в [docs/STATUS.md](docs/STATUS.md).
